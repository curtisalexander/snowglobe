The 5-minute leader briefing

The model sees what comes back.

A coding agent is not one magic box. It is an LLM that requests plus a harness that acts. When a tool runs, the model does not see the database—it sees what the approved program returns.

The memorable version

The LLM requests. The harness executes. The program controls what comes back.

The design principle

Put a controlled program between the model and the data.

This is indirection: the model requests a reviewed program instead of handling the rows itself. Let the LLM plan. Let narrow, tested, deterministic code compute. Predictable code is easier to govern—but it is safe only when its access and output are also controlled.

Bad · direct handling“Query the table, inspect the rows, and calculate the answer.”
Better · controlled indirection“Run the approved check and return only its safe result.”
Watch every return path

Snowflake is not the only way data reaches context.

Anything a tool exposes in its result—including printed output, errors, logs, and previews—can be fed back to the model. Data used only inside the controlled program stays out of context. The same boundary test applies everywhere: what comes back?

▤

Reading a local CSV

If the agent runs cat customers.csv or asks a file tool to read it, those values can enter context. “Local” does not mean “invisible to the model.”

›_

Printing from Python

An aggregation may be safe; dumping the underlying DataFrame is not. Standard output and error output normally return to the harness.

⌕

Preview and debug output

Sample rows, stack traces, logs, notebook display calls, and “helpful” previews can expose values just as easily as a query result.

Σ

Approved summaries

Counts and aggregates still enter context. Use policy-approved thresholds and suppression rules: small groups and rare combinations can still reveal people.

↗

Artifact references

A path or object identifier is safer only when the agent cannot later read the raw artifact through another tool. Protect the whole path.

◈

Human-provided results

Pasting output into chat also sends it into context. A person should share only the minimum approved summary—or share nothing.

⚠

Rules are guidance, not a guaranteed boundary.

“Never show sensitive data” is worth saying, but an LLM does not follow instructions perfectly. Enforce the boundary with approved tools, least-privilege Snowflake roles, masking, output limits, and deterministic return contracts—not trust alone.

There is still enormous value

We can do a lot without giving the model raw data.

The coding agent can create and improve the machinery around an analysis. Access to sensitive values is only one small part of the work.

OPTION 01 · CONTROLLED EXECUTION

Let the harness run an approved program.

Useful when fast feedback matters and governance supports automated execution.

  • Validate SQL syntax and schemas
  • Run tests and data-quality checks
  • Return approved counts, metrics, or status
  • Detect failures and revise the code
  • Repeat a documented workflow consistently
OPTION 02 · HUMAN EXECUTION

Let the agent draft. Let a qualified person review and run.

Useful when data access is too sensitive or automated execution is not approved.

  • Agent drafts SQL, Python, tests, and runbooks
  • Person reviews data access, outputs, network calls, and write operations
  • Person runs with least privilege in the approved environment
  • Person shares only a safe summary if useful
  • If even the summary is sensitive, they share nothing

Take this with you

Do not connect a curious model directly to sensitive data and hope it behaves.

Put a narrow, reviewed, deterministic program in the middle. Control what it can access. Control what it returns. Apply the same rule to every later tool.
