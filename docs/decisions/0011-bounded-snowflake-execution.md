# ADR 0011: Bounded asynchronous Snowflake execution

- **Status:** Accepted
- **Date:** August 19, 2026
- **Builds on:** [ADR 0009](0009-constrained-snowflake-mvp-budgets.md) and
  [ADR 0010](0010-minimum-snowflake-select-policy.md)

## Context

The synthetic executor and viewer stream already prove the closed MCP lifecycle and
failure-atomic browser protocol, but they do not define when a real Snowflake request
is controllable or complete. Returning `accepted` before a cursor exists would create
a cancellation gap. Marking a request complete before Arrow admission would let the
viewer discover work whose schema, cells, rows, or serialized form can still fail.

The process-local broker must retain a complete admitted result until the analyst
opens it. Files and browser persistence are prohibited, while the fixed MVP result is
small enough to retain as bounded record batches in process memory.

## Decision

- Run the synchronous Snowflake connector in a worker thread. Return `accepted` only
  after policy authorization, pending broker registration, connection and cursor
  creation, private cursor registration, and background-task startup all succeed.
- Execute only SQL regenerated by the policy, passing the 60-second connector timeout
  in addition to the fixed statement, queue, network, socket, and detached-query
  settings from ADR 0009.
- Set `client_prefetch_threads=1` and consume `fetch_arrow_batches()` incrementally.
  Convert only the current PyArrow table to its record batches; never call
  `fetch_arrow_all()`, `fetchall()`, `to_pylist()`, or construct row dictionaries.
- Preserve the connector's Arrow schema, names, metadata, and types. Reject a schema
  change between tables rather than coercing or concatenating them.
- Run row, column, cell, decoded-byte, and serialized-Arrow admission while fetching.
  Retain only admitted record batches, bounded by the 50-row and 256-KiB MVP budgets,
  in the process-local broker. Publish `complete` only after the iterator finishes,
  Arrow stream finalization passes, and the cursor and connection close.
- When `fetch_arrow_batches()` yields nothing, require every public connector result
  batch to report zero rows and use the first result batch's public `to_arrow()` method
  only to recover the schema-preserving empty table. Any inconsistent empty-result
  metadata fails closed.
- Keep an application-owned expiry task in addition to connector and server timeouts.
  Cancellation, expiry, shutdown, execution failure, schema mismatch, and admission
  overflow cancel the registered cursor where applicable and never publish a source.
  One process-local execution lock independently prevents concurrent connections.
- Keep configured execution opt-in at process launch through an analyst-selected local
  config path and profile. Tool inputs cannot select connection settings. Starting
  without that explicit configuration preserves the fixed `SERVICE_UNAVAILABLE`
  submission behavior.

## Consequences

- MCP acceptance means the request is immediately controllable, but not that execution
  or result admission succeeded.
- The broker stores one complete bounded Arrow result as record batches, not as a
  concatenated table, serialized blob, local file, or browser-persistent dataset.
- Snowflake may materialize one connector result table before Snowglobe can measure
  it. The server-owned 51-row SQL cap, one prefetch thread, conservative cell budget,
  and immediate per-table admission bound Snowglobe's available controls; the
  constrained warehouse remains an independent resource backstop.
- Empty results preserve their Snowflake-provided Arrow schema and complete normally.
- Real credentials and connected execution remain prohibited until Gate 4 assurance
  passes and the Gate 5 procedure updates `SECURITY.md`.
